## Установка WinAFL:
1. Download DynamoRIO (https://github.com/DynamoRIO/dynamorio/releases)
2. Download WinAFL sources (https://github.com/googleprojectzero/winafl.git)
3. Install Visual Studio with C++ Development tools  
4. Open WinAFL folder in Visual Studio
5. In Visual Studio open Terminal
6. 
```
mkdir build64
cd build64
cmake -A x64 .. -DDynamoRIO_DIR=C:\path\to\DynamoRIO\cmake -DINTELPT=1
cmake --build . --config Release
```

## ФАЗИМ DLL - Алгоритм действий:  
1. Найти DLL который что-то парсит/обрабатывает.
2. Найти функцию в DLL которая принимает файлы на вход и запускает обработку.
3. Изучаем аргументы функции.
4. Создаем harness с этой функцией.
5. Проверяем работоспособность.
6. Фазим.

Дополнительно: в некоторых случаях нужно будет реверсить EXE/DLL и искать в них намеки на функции обработки данных. Это мы также затронем, так как это и есть одна из основных причин непонимания фазинга на Windows.  

## ФАЗИМ DLL - Процесс:  
Описанный здесь подход относится к black box тестированию (без наличия исходного кода). При наличии исходного кода, инструментация проходит просто и быстро: мы просто компилируем с помощью AFL компилятора программу или harness. В Windows зачастую приходится работать с 
программами чей код закрыт, поэтому нам нужно использовать "компиляцию в runtime" ("на лету").  

Предположим, что мы нашли цель, желательно которая может принимать аргументы через CLI. Как понять какая библиотека вызывается (DLL)? В этом нам могут помочь такие программы:  
- ProcMon (Открываем app -> Загружаем файл -> Смотрим какие DLL загружаются, используемые функции и т.д.)
- x64dbg (отлавливаем вызовы: CreateFileW, ReadFile, fread и смотри call stack)
- Если есть экспортируемые функции: dumpbin /exports target.dll
- Если есть экспортируемые функции: dumpbin /exports target.dll
- IDA / Ghidra реверс, поиск по строкам и сигнатурам


**Поиск сдвига функции в EXE (WinDBG)**:  
```x <EXE_NAME>!<FUNCTION_NAME>```  

**Формулы поиска offset**:  
DLL:
```DLL base - Function location = offset```  
EXE:
```EXE base - Function location = offset```  

**PageHeap**:  
Данный функционал позволяет добавить проверки ошибок памяти, такие как heap corruption, buffer overflow.  
Дополнительная документация: https://learn.microsoft.com/ru-ru/windows-hardware/drivers/debugger/gflags-and-pageheap  
```gflags.exe /p /enable <prog.exe>```

## Фазинг бинарника  
Перед началом фазинга необхоимо установить DynamoRIO и WinAFL. В примере ниже сперва нам необходимо найти функцию которую будем фазить, для этого нужно дизассамблировать бинарник и изучить его функции, аргументы функций. Псоле того, как нашили интересующую нас функцию, нужно определить её адресс в программе, затем найти сдвиг (начало функции - начало программы).

1. ```afl-fuzz.exe -i input -o outpud -D path/to/DynamoRIO/binary -t <timeout for each run> -m <memory limit for the target process> -- -coverage_module <> -target_module <prog/module that contain target function> --target_offset <offset> -fuzz_iterations <number of iterations> -- harness.exe @@```


**Анализ crashes**:  
Для анализа багов и создания отчетов будем использовать утилиту https://github.com/SkyLined/BugId.git.  

Создание отчета: ```python.exe BugId.py prog.exe -- poc```
