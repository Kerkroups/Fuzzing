Динамическая библиотека состоит из подпрограмм, которые подгружаются в нашупрограмму во время её выполнения. При компиляции программы, которая использует динамическую библиотеку, эта библиотека не становится частью нашего исполняемого файла - она так и остается отдельным модулем. В Windows - .dll, в Linux - .so; Одним из преимуществ является то, что разные программымогут использовать одну копию динамической библиотеки, также её можно обновить без необходимости перекомпиляции всех исполняемых файлов, которые её используют.  

Библиотека импорта - это библиотека, которая автоматизирует процесс подключения и спользования динамических библиотек. Библиотека импорта и динамическая библиотека должны иметь одинаковые имена.  

Просмотр символьной информации исполняемого файла:  
```readelf --syms file.out ```  
Эта информация нужна для отладки. Содержит имена используемых библиотек и функций.  

Разделение исполняемого файла. Это нужно для определения динамических библиотек используемых в программе.  
```
strip --strip-all file.out
readelf --syms file.out
```
В таблице .dynsym будут находиться имена динамических библиотек.

Дизассамблирование исполняемого файла: ```objdump -M intel -d file.out```  

Показать используемые зависимости: ```ldd file.out```. ldd может запустить исполняемый файл для обнаружения зависимостей в системе, поэтому лучше всего запускать неизвестный файл на VM.  

Восстановление искаженных имен функций бинарного файла:
```
nm -D file.out
nm -D --demangle file.out
```

Переменная окружения LD_LIBRARY_PATH используется для того, чтобы исполняемый файл нашел библиотеку.  
Перменная окружения LD_PRELOAD - переменная среды которая влияет на поведение динамического компоновщика. Она позволяет указать одну или несколько библиотек, которые компоновщик должен загрузить перед любой другой библиотекой, включая стандартные системные библиотеки.  

## PLT  
Procedure linkage table (writable section). Секция кода, содержащая исполняемый код, также как и в секции .text. Состоит полностью из заглушек строго определенного формата, предназначенных для перенаправления вызовов из секции .text в соотвествующие места библиотек.  
```objdump -M intel --section .plt -d file.out```  

Когда вызывается функция из динамической библиотеки, выполняется вызов в код PLT; код из PLT обращается к линкеру (_dl_runtime_resolver) который ищет в библиотеке адрес вызываемой функции. После нахождения, адресс вызываемой функции записывается в GOT. После того, как адрес был найден он будет выполнен, как только код функции будет выполнен управление будет переданно сохраненному адресу возврата. В следующий раз, когда снова будет вызываться функция (которыю уже вызвали один раз) адрес будет взят из GOT, PLT не будет снова обращаться к линкеру. Как итог: PLT определяет адресса функций динамических библиотек обращаясь к динамическому линковщику, после чего адреса записываются в GOT. После повторного вызова запрашиваемой функции её адрес будет взят из GOT.
