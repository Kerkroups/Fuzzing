## HEAP  

**Для чего нужен heap?**: Это область памяти, где программа хранит массивы, объекты, динамические структуры. [Wikipedia](https://ru.wikipedia.org/wiki/%D0%9A%D1%83%D1%87%D0%B0_(%D0%BF%D0%B0%D0%BC%D1%8F%D1%82%D1%8C))  

**Функции работы с памятью**:  
Функции malloc() и calloc() используются для динамического выделения памяти в heap. Разница между этими функциями в том, что malloc() перед выделением памяти не обнуляет её, а calloc() перед выделением памяти обнуляет её. Для использования malloc() и calloc() нужно подключить библиотеку <stdlib.h>.  

Функции для работы с памятью:  
- malloc()
- calloc()
- realloc()
- free()  

**Терминология malloc()**:  
- Chunk — отдельный блок памяти, который выдаёт malloc().
- Heap — большой участок памяти, содержащий множество чанков.
- Arena — менеджер, который управляет кучами и свободными чанками.
- Mutex — блокировка, защищающая структуры арены от одновременного изменения несколькими потоками.
- Tcache — небольшой локальный кэш свободных чанков для конкретного потока.
- Memory - часть адресного пространства приложения, которая, как правило, размещается в оперативной памяти (RAM) или в области подкачки.

Функция ```malloc``` из библиотеки glibc работает по принципу блоков. Она разделяет большой участок памяти («heap») на блоки различного размера. Каждый блок содержит метаданные о своём размере (через поле size в заголовке блока) и, следовательно, о расположении соседних блоков. Когда блок используется приложением, единственной «запоминаемой» информацией является его размер. При освобождении блока память, ранее занимавшая данными приложения, перепрофилируется для хранения дополнительной информации, связанной с ареной, например указателей в связных списках, что позволяет быстро находить подходящие блоки и повторно использовать их при необходимости.  

Поскольку все блоки кратны 8 байтам, 3 младших бита размера блока можно использовать для флагов:  
- A (0x4)
- M (0x2): блок, выделенный с помощью mmap — этот блок был выделен одним вызовом функции mmap и вообще не входит в состав кучи.  
- P (0x1): предыдущий блок используется — если этот бит установлен, предыдущий блок по-прежнему используется приложением, и, следовательно, поле prev_size является недействительным.

Обратите внимание, что, поскольку чанки расположены в памяти один за другим, если вам известен адрес первого чанка (самый младший адрес) в куче, вы можете пройтись по всем чанкам в куче, используя информацию о размере, но только в порядке возрастания адресов, хотя определить, когда вы дошли до последнего чанка в куче, может быть сложно. Выделенные кучи всегда выравниваются по адресу, являющемуся степенью числа два.  

**Память хранится в кучах (heaps), которые состоят из чанков (chunks). Кучами управляют арены (arenas). Для безопасной работы нескольких потоков каждая арена защищена мьютексом (mutex). Чтобы ещё больше ускорить выделение памяти, каждый поток имеет собственный небольшой кэш свободных чанков — tcache, из которого память часто выдаётся без обращения к арене**.

![](https://sourceware.org/glibc/wiki/MallocInternals?action=AttachFile&do=get&target=MallocInternals-heaps.svg)

**heap chunk: metadata + userdata**;  
- metadata: prev_size, size; где prev_size - размер предыдущего chunk, size - размер текущего chunk.  
- Чанки следуют друг за другом. Вычисление следующего чанка находится так: ```next_chunk = chunk + chunk->size```

Код структуры malloc_chunk:  
```
struct malloc_chunk {

    INTERNAL_SIZE_T mchunk_prev_size; /* Size of previous chunk (if free).  */
    INTERNAL_SIZE_T mchunk_size;      /* Size in bytes, including overhead. */

    struct malloc_chunk *fd; /* double links -- used only if free. */
    struct malloc_chunk *bk;

    /* Only used for large blocks: pointer to next larger size.  */
    struct malloc_chunk *fd_nextsize; /* double links -- used only if free. */
    struct malloc_chunk *bk_nextsize;
};
```

```free(ptr)```: Освобовить память. После освобождения чанка структура чанка меняется:  
```| prev_size | size | fd | bk | unused space |```  

fd - forward pointer;  
bk - backward pointer;  

В данный момент используется **tcache**:  ```| prev_size | size | next (fd) |```  
- prev_size - размер предыдущего chunk;  
- size - размер текущего chunk;  
- next(fd) - указатель на следующий chunk;

Зачем нужен tcache?

Раньше при free() чанк обычно возвращался в структуры арены (например, fastbins или bins), что требовало работы с общими данными арены. В современных glibc небольшой освобождённый чанк сначала кладётся в tcache текущего потока. о есть malloc() даже не обращается к арене и не трогает её мьютекс. Это сильно ускоряет выделение памяти и уменьшает конкуренцию между потоками.  

``` malloc(64) ->  chunk A -> free(A) -> tcache -> malloc(64) -> chunk A из tcache```  

Пример для free() и malloc(): в этом примере Я пытался понять что такое use-after-free. "Use-after-free" это уязвимость, когда память используется после освобождения. 
```
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void){
        char *str = "SECRET_DATA";
        char *buf = malloc(sizeof(char) * strlen(str) + 1);
        strncpy(buf, str, strlen(str));
//---------------------------------------------------------
        printf("buf data: %s\n", buf);
        printf("buf address: %p\n", buf);  // Отобразит адрес данных в HEAP;
        printf("buf address: %p\n", &buf); // Отобразит адрес переменной в STACK;
//---------------------------------------------------------
        printf("Freeing memory\n");
        free(buf);
        printf("buf data afted free(): %s\n\n", buf);
//---------------------------------------------------------
        char *buf2 = malloc(sizeof(char) * strlen(str) + 1);
        strcpy(buf2, "HELLO_WORLD");
        printf("buf2 data: %s\n", buf);
        printf("buf2 address is: %p\n", buf2);
        printf("buf2 address: %p\n", &buf2);
        return 0;
}
```
Результат:
```
buf data: SECRET_DATA
buf address: 0x555555559310 // Адрес в HEAP;
buf address: 0x7fffffffdbd0 // Адрес в STACK;
Freeing memory
buf data afted free(): YUUU

buf2 data: HELLO_WORLD
buf2 address is: 0x555555559310
buf2 address: 0x7fffffffdbc8
```

После free() malloc() записыват в пользовательскую часть fd и bk;  
Когда блок памяти больше не нужен, его необходимо освободить, иначе он навсегда останется в «зарезервированном» состоянии и никогда не будет использован повторно.

## STACK:  
В контексте программирования на Си, стек обозначает определенную автоматичкски выделяемую область памяти в которой хранятся локальные переменные, параметры функции и адресс возврата (ячейка памяти в которую процессор должен вернуться после завершения выполнения функции).  
[Дополнительная информация](https://www.geeksforgeeks.org/operating-systems/introduction-to-stack-memory/)  

При вывозе функции программа должна запомнить, куда ей нужно вернуться после завершения работы функции. Это обеспечивается с помощью стэка вызовов - область памяти, которая увеличивается и уменьшается по мере вызова и возврата функции. Обычно при вызове функции:  
1. Адрес команды, следующей за вызовов (адрес возврата), помещается в стэк.
2. Параметры функции могут помещаться в стэк или передаваться через регистры.
3. Переменные объявленные внутри тела функции размещаются в стэке.

Когда функция завершает работу, адрес возврата снимается со стэка и программа продолжает выполнение инструкции по этому адресу.  

**Stack frame**:  
```
-----------
Argument_1
Argument_2
Argument_3
Saved Return Address // Сохраняется во время инструкции CALL;
Saved RBP            // Если функция использует регистр RBP как указатель фрейма.
LocalVariable_2
LocalVariable_1
...
Low Memory Address
Stack Pointer (RSP)  // Указывает на вершину стека.
-----------
```
