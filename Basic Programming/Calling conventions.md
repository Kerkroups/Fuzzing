**Function prologue example**:  
Во время выполнения функции rbp остаётся неизменным и указывает на начало своего стекового кадра. Локальные переменные и стековые аргументы можно адресовать относительно rbp. Старое значение rbp сохраняется для последующего восстановления в эпилоге. Затем устанавливается новое значение rbp, равное текущему верху стека (где, кстати, теперь хранится старое значение rbp). Затем в стеке выделяется память для локальных переменных путем вычитания их общего размера из rsp. Это и есть автоматическое выделение памяти в языке C, и именно этот метод мы использовали в самом первом задании для выделения буферов в стеке.
```
push rbp
mov rbp, rsp
sub rsp, 24
```

**Function epilogue example**:  
Переместив начальный адрес стекового фрейма в rsp, мы можем быть уверены, что вся память, выделенная в стеке, будет освобождена. Затем восстанавливается прежнее значение rbp, и теперь rbp указывает на начало предыдущего стекового фрейма. Наконец, команда ret извлекает адрес возврата из стека и помещает его в rip.  
```
mov rsp, rbp
pop rbp
ret
```
OR  
Иногда компилятор выбирает полностью эквивалентную альтернативную форму. Инструкция "leave" предназначена специально для уничтожения стека. Ее аналог, инструкция "enter", не всегда используется компиляторами, поскольку она более функциональна, чем приведенная выше последовательность инструкций.
```
leave
ret
```  
После выхода из функции наша работа не всегда считается завершённой. Если в функцию передавались аргументы, хранящиеся в памяти (на стеке), их тоже необходимо удалить.
